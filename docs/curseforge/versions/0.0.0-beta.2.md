<h2>v0.0.0-beta.2 - Client crash fix (gray shader) + item models</h2>

<p>Fixes a hard client crash on resource load and three broken item models, both left over from the 26.2 &rarr; 1.21.1 asset port. No gameplay, dependency or loader-version changes.</p>

<h3>Fix</h3>
<ul>
<li><strong>Client crash on startup / resource reload</strong>: <code>RegisterShadersEvent</code> threw <code>FileNotFoundException: ascendant_equipment:shaders/core/gray.json</code>. The port shipped only <code>gray.fsh</code> (and in the post-1.21.1 GLSL dialect). Restored the full <code>gray.json</code> / <code>gray.vsh</code> / <code>gray.fsh</code> shader set in 1.21.1 format (<code>#version 150</code>, <code>linear_fog</code>), taken from upstream Apotheosis 1.21.</li>
<li><strong>Item models <code>gem_dust</code> and <code>godforged_pearl</code></strong>: used the 1.21.4+ texture-object syntax (<code>"layer0": { "sprite": ..., "neoforge_data": ... }</code>), which 1.21.1 cannot parse &mdash; the items rendered as the missing-model placeholder. Converted <code>layer0</code> to the plain-string form. The per-texture <code>light_emission</code> hint (unsupported on 1.21.1) is dropped; the <code>.mcmeta</code> animations are kept.</li>
<li><strong>Item <code>god_fused_pearl</code></strong>: had no <code>models/item/god_fused_pearl.json</code> (only a 1.21.4-style <code>items/</code> definition, which 1.21.1 ignores). Added the model as a parent reference to <code>godforged_pearl</code>, matching the original intent.</li>
</ul>

<h3>Notes</h3>
<blockquote>Shader compilation can only be verified in-client (needs a GL context); the shader sources are a verbatim port of upstream Apotheosis 1.21 for the same Minecraft version. <code>./gradlew build</code> passes.</blockquote>
