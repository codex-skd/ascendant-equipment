<h2>v0.0.0-beta.18 - Codec & Registry Initialization Fix</h2>

<h3>Critical Bugfixes</h3>
<ul>
<li><strong>Issue</strong>: All dynamic registries returned 0 entries (rarities, gems, invaders, elites, augments), causing JSON parsing errors and empty gameplay systems.</li>
<li><strong>Root Cause</strong>: <code>initCodecs()</code> calls for LootRule, SpawnCondition, EntityModifier, and GemBonus dispatch types were missing from the mod constructor. Without these, all codec-based deserialization failed silently.</li>
<li><strong>Regression</strong>: In previous beta, <code>ConfigPayload</code> registration was also missing, causing client network errors on world join.</li>
</ul>

<h3>What's Fixed</h3>
<ul>
<li>✅ 5/5 Rarities load correctly (common, uncommon, rare, epic, mythic)</li>
<li>✅ 21/21 Gems load correctly (core, overworld, the_nether, the_end domains)</li>
<li>✅ 93/93 Affixes load correctly (melee, ranged, armor, breaker, shield, generic)</li>
<li>✅ 23/23 Invaders load correctly (overworld, nether, end)</li>
<li>✅ Elites (4), Augments (1), and other registries load correctly</li>
<li>✅ Config sync no longer crashes on world join</li>
<li>✅ All 7 network payloads properly registered</li>
<li>✅ EquipmentEvents and AscEqMobEvents now active on NeoForge event bus</li>
<li>✅ 12 dynamic registries correctly subscribed to server reload events</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li>Added <code>LootRule.initCodecs()</code>, <code>SpawnCondition.initCodecs()</code>, <code>EntityModifier.initCodecs()</code>, <code>GemBonus.initCodecs()</code> to constructor</li>
<li>Added <code>EquipmentConfig.ConfigPayload.Provider</code> registration</li>
<li>Added all missing imports for codec types and payload providers</li>
<li>Added Mixin annotation processor in build.gradle for refmap generation</li>
</ul>

<h3>Build Requirements</h3>
<ul>
<li>Minecraft: 1.26.2</li>
<li>NeoForge: 26.2.0.37-beta or later</li>
<li>Java: 21+</li>
</ul>
