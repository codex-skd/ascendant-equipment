<h2>v0.0.0-beta.15 - Critical Registrations Fix</h2>

<h3>Critical Bugfix</h3>
<ul>
<li><strong>Issue</strong>: JEI recipe viewer crashed when displaying Affix smithing recipes (Malice, Supremacy, Unnaming). Dynamic registries (Rarities, Gems, Affixes, Invaders, Elites, etc.) never received data from datapacks because <code>registerToBus()</code> calls were missing in the common setup lifecycle.</li>
<li><strong>Root Cause</strong>: The port was missing 12 <code>registerToBus()</code> calls that the original Apotheosis has in its <code>FMLCommonSetupEvent</code>. Without these, dynamic registries did not subscribe to server reload and network sync events.</li>
</ul>

<h3>What's Fixed</h3>
<ul>
<li>✅ 12 dynamic registries now properly register to the event bus (Rarity, RarityOverride, Affix, ExtraGemBonus, Gem, AffixLoot, Invader, RogueSpawner, Elite, PurityWeights, Augment, TierAugment)</li>
<li>✅ EquipmentEvents and AscEqMobEvents now registered on NeoForge.EVENT_BUS (they were never active)</li>
<li>✅ 6 network payloads properly registered (BossSpawn, RerollResult, RadialState, WorldTier, LinkItemToChat, GemCaseSelect)</li>
<li>✅ JEI recipe extensions no longer crash with NoSuchElementException</li>
<li>✅ Defensive empty-list checks added to JEI extensions as secondary safeguard</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li>Added 12 <code>registerToBus()</code> calls in <code>AscendantEquipment.commonSetup()</code></li>
<li>Registered <code>EquipmentEvents</code> and <code>AscEqMobEvents</code> on NeoForge event bus</li>
<li>Registered all 6 network payloads via <code>PayloadHelper.registerPayload()</code></li>
<li>Added Mixin annotation processor in build.gradle for refmap generation</li>
<li>Added <code>mixin_version=0.8.7</code> and <code>mixin=true</code> to gradle.properties</li>
<li>Added empty-list guards in MaliceExtension, SupremacyExtension, UnnamingExtension</li>
</ul>

<h3>Build Requirements</h3>
<ul>
<li>Minecraft: 1.26.2</li>
<li>NeoForge: 26.2.0.37-beta or later</li>
<li>Java: 21+</li>
</ul>
